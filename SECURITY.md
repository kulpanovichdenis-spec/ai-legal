# Границы безопасности

Сервис предназначен для доверенной корпоративной сети. Стандартный Compose публикует порт только на loopback. Доступ сотрудников следует организовать через согласованный внутренний контур и управляемый прокси с TLS. Открывать эту сборку напрямую в интернете с реальными документами и чатами нельзя.

| Область | Особенность текущей версии |
| --- | --- |
| Вход | Администратор входит с паролем. Путь входа сотрудника выдаёт сессию по имени и может создать аккаунт. Человек, знающий имя сотрудника, может выдать себя за него. Отключение самостоятельной регистрации с паролем не отключает этот путь. |
| Библиотека | Документы принадлежат экземпляру. Теги режима управляют подбором контекста, а не правами доступа. Шаблоны доступны авторизованным пользователям. Изоляции организаций и личных библиотек нет. |
| История и хранилище | Администратор может просматривать диалоги. SQLite, файловое хранилище, индекс, журналы и резервные копии требуют контроля доступа. В хранилищах могут быть исходный текст и персональные данные. |
| Передача модели | Внешней модели могут передаваться запрос, история, фрагменты вложений, инструкции и результаты поиска. Вспомогательные вызовы и интеграции тоже требуют проверки. Маскирование отдельных типов данных и предупреждения при загрузке зависят от режима и не гарантируют обезличивание. |
| Публикации | Публичные API проектов и публикация из чата выключены по умолчанию. Если оператор включает их, опубликованные слайды и имя автора доступны без входа. Проверяйте материалы до команды публикации. |
| Внешние интеграции | При настройке Bitrix24 и DaData часть данных передаётся за пределы приложения. Доступ и состав данных согласуются оператором отдельно. |

До работы с реальными документами настройте доступ к серверу и тому, проверьте маршруты исходящих запросов и согласуйте правила загрузки, хранения, резервирования и удаления. Сначала прогоните поток на синтетических материалах. Предупреждение о возможных персональных данных появляется после загрузки и не заменяет проверку файла оператором.

Для размещения сервиса в интернете понадобятся подтверждаемая идентичность, проверенные права на все объекты, изоляция данных между организациями или пользователями, ограничения обработки файлов и проверка фактических запросов к провайдерам. Публичное распространение кода само по себе не требует предоставлять доступ к рабочей установке.
