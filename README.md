# Юридический AI-ассистент

Веб-приложение для юридической службы и сотрудников бизнеса. Помогает ответить на типовой вопрос, найти пункт во внутреннем регламенте, разобрать договор или подготовить черновик письма. Проект создавался для установки на внутреннем сервере компании. Исходный код проекта размещается в репозитории [kulpanovichdenis-spec/ai-legal](https://github.com/kulpanovichdenis-spec/ai-legal). Каждый оператор выбирает свой сервер и хранит данные своей установки.

> **Граница применения.** Используйте ассистента для справки и подготовки черновиков. Сверяйте ссылки и формулировки с исходными документами. Сложные, спорные и значимые для бизнеса вопросы передавайте юристу. Разворачивайте сервис в доверенном контуре. Вход сотрудника в этой версии подтверждает только введённое имя, а документы библиотеки общие для экземпляра.

## Что можно делать

| Режим | Что дать на вход | Что ожидать |
| --- | --- | --- |
| Авто | Описание задачи и, при необходимости, файл | Ассистент выбирает сценарий по формулировке и вложениям. Если выбор неверен, переключите режим вручную. |
| Консультация | Краткий вопрос, роль сторон и существенные обстоятельства | Первичное объяснение, уточняющие вопросы и ориентиры для проверки. |
| Регламенты | Вопрос о процессе или правиле из загруженных документов | Поиск по внутренней базе и ответ с отсылкой к найденному материалу. При отсутствии основания уточните запрос или добавьте источник. |
| Документы | Договор, исходные условия или описание нужной формы | Резюме и замечания по договору, проекты писем, уведомлений, претензий и допсоглашений. Режим также помогает находить загруженные типовые формы. |
| Проверка рекламы | Текст или изображение объявления, тип продукта, при наличии — документы о нём | Перечень возможных рисков и правок. Встроенные инструкции ориентированы на российский контекст, включая отраслевые проверки. Актуальность требований проверяет профильный юрист. |
| Презентация | Задача, ход работы, результат и следующие шаги | Черновик для бизнес-заказчика. Режим доступен администратору. Публичные страницы и публикация из чата отключены по умолчанию. |

### Договоры и юридические документы

- **Саммари договора.** Из приложенного договора выделяет предмет, сроки, цену и порядок оплаты, обязательства сторон, условия прекращения, ключевые риски и вопросы для проверки. Можно задать конкретный вопрос по пункту договора.
- **Подготовка черновиков.** По договору и описанию изменений составляет дополнительное соглашение, протокол разногласий, письмо, претензию или уведомление. Указывает поля, для которых нужны данные сторон. Черновик можно скачать в DOCX, историю чата — в DOCX или PDF.
- **Типовые формы.** Помогает подобрать форму по виду сделки и роли сторон. Выдаёт настроенную ссылку из каталога или файл из общей библиотеки. Администратор задаёт названия, статус форм и связанные приложения.
- **Возврат и замена товара.** Помогает сотруднику собрать исходные сведения, найти утверждённую форму и подготовить черновик ответа по настроенной процедуре организации.

### Поиск и обработка файлов

- **OCR сканов и изображений.** Извлекает текст из PDF с текстовым слоем. Для сканов и страниц без текста использует Tesseract с русским и английским распознаванием. В проверке рекламы дополнительно распознаёт графические элементы PDF. Сверяйте с оригиналом суммы, даты и мелкий текст.
- **Библиотека и поиск.** Администратор загружает регламенты и справочные материалы пакетами до десяти файлов. ChromaDB и BM25 подбирают контекст по смыслу и ключевым словам. Чат также принимает разовые вложения. Для ответа по регламенту нужен загруженный текст, а для навигации достаточно настроенной карточки со ссылкой.
- **Обезличивание вложений.** В сценариях с соответствующей политикой анонимайзер подменяет распознанные ФИО, контакты, паспортные и другие данные метками. При формировании ответа приложение может восстановить исходные значения. Базовое распознавание использует шаблоны, дополнительно доступен NER через Natasha. Библиотека показывает предупреждение о возможных персональных данных после загрузки. Маскирование зависит от сценария и не гарантирует защиту текста запроса, истории, скиллов или найденных фрагментов. Подробнее в [ограничениях безопасности](SECURITY.md).

### Интеграции и администрирование

- **Bitrix24.** Из веб-чата можно создать задачу через REST-вебхук: пользователь проверяет название и описание, сервис назначает настроенного ответственного и пытается приложить историю чата в DOCX. Отдельный канал бота принимает сообщения через входящий вебхук и отправляет ответ в диалог Bitrix24. Обе возможности требуют самостоятельной настройки и разрешения на передачу данных.
- **DaData.** При настроенной интеграции ищет российские организации по ИНН или ОГРН и помогает сопоставить найденные реквизиты с договором. Результаты служат для предварительной проверки.
- **Интерфейс и управление.** Потоковые ответы, история диалогов, инструкции и скиллы по сценариям. Администратор управляет библиотекой и пользователями, может просматривать чаты и статистику использования. Публикация презентаций отключена по умолчанию.

## Как строится ответ

1. Пользователь выбирает режим или оставляет автоматический выбор. Сценарий определяет инструкции, дополнительные правила и допустимые инструменты.
2. Сервер извлекает текст из вложения. По необходимости он ищет релевантные фрагменты в библиотеке гибридным поиском по смыслу и ключевым словам. Настроенные администратором инструкции и скиллы дополняют контекст.
3. Сервер передаёт запрос с отобранным контекстом выбранной модели и показывает потоковый ответ. Качество зависит от модели, состава библиотеки, извлечения текста и формулировки вопроса.

| Подключение модели | Когда использовать | Как выбирается |
| --- | --- | --- |
| OpenRouter | Для пробного запуска на синтетических данных или при разрешённом внешнем провайдере | В `OPENROUTER_MODEL` указывается идентификатор `provider/model`, ключ задаётся на сервере. |
| Внутренний OpenAI-совместимый сервер | Когда обработка должна идти на разрешённом сервере в контуре компании | Укажите имя в формате `name:tag` и `INTERNAL_API_URL` с базой API. Отдельно проверьте сетевой доступ из контейнера. |

Базовая модель используется по умолчанию. Оператор может задать модели для отдельных режимов и маршрутизатора. Для внутреннего профиля проверяйте все переопределения, включая вспомогательные вызовы. Точный порядок описан в [инструкции запуска](docs/QUICKSTART.md).

## Что настроить под свою организацию

Чистый запуск создаёт пять инструкций режимов и девять скиллов из каталога [starter_content](backend/starter_content). В набор входят правила консультации, регламентов и работы с договорами, отраслевой чек-лист рекламы, заготовки претензий и уведомлений и правила навигации по типовым формам. Инструкции ориентированы на российский контекст. Перед применением в работе проверьте применимость правил, а для отраслевых сценариев согласуйте их с профильным юристом.

1. В **Скиллах** откройте **Каталог документов и типовых форм**. Замените тестовые названия и адреса на действующие, добавьте свои реквизиты, документы для контрагентов, перечень форм и контакт юридической службы. Навигатор и режим «Регламенты» берут ссылки из этой карточки.
2. В скилле **Возврат и замена товара потребителю** заполните основания, категории, сроки, ответственных, канал передачи и ссылки на утверждённые формы. Пустая карточка даёт возможность уточнить факты и направить вопрос владельцу процесса.
3. В **Документах** загрузите текст регламентов для поиска и файлы шаблонов для скачивания. Каталог хранит ссылки, а ответы по содержанию опираются на загруженные источники.

Встроенные карточки используют вымышленные записи на example.test. Заполнение карточек и [проверка результата](docs/QUICKSTART.md#проверка-на-примере) входят в настройку экземпляра.

## Запуск и настройка

**Установка агентом.** Поручите агенту с терминалом установку по [AGENTS.md](AGENTS.md). Он проверит инструкции и скиллы, запросит недостающие параметры, настроит экземпляр и после подтверждения выполнит согласованные push и deploy. Порядок действий и вопросы для администратора собраны в [регламенте установки агентом](docs/AGENT_SETUP.md).

1. [Установить и запустить](docs/QUICKSTART.md) — Docker Compose, секреты, выбор модели и проверка первого запуска.
2. [Добавить документы и инструкции](docs/QUICKSTART.md#документы-и-настройки) — общие регламенты, скачиваемые шаблоны, разовые вложения и скиллы.
3. [Проверить на синтетическом примере](docs/QUICKSTART.md#проверка-на-примере) — тестовый регламент в комплекте.
4. [Оценить ограничения безопасности](SECURITY.md) — вход по имени, доступ администратора, хранение, внешние запросы и условия внутреннего развёртывания.

Компоненты установки: React/Vite, FastAPI, SQLite, ChromaDB и BM25. Nginx обслуживает веб-интерфейс и проксирует API. Compose по умолчанию слушает `127.0.0.1:8080` и хранит данные в отдельном Docker-томе. Для доступа сотрудников нужен управляемый вход во внутренней сети.
