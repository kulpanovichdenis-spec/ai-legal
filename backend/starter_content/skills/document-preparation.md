# Скилл: подготовка юридических документов — оформление

Этот скилл задаёт ОФОРМИТЕЛЬСКИЕ правила и каркас для документов в режиме «Документы». Структура и правовая база для отдельных видов документов берутся из специализированных скиллов:
- **claim-templates** («Типовые шаблоны претензий») — для претензий.
- **notice-templates** («Типовые шаблоны уведомлений») — для уведомлений (нарушение, односторонний отказ, непродление, зачёт, приостановление исполнения, расторжение по соглашению).

В этом скилле — только то, что общее для всех документов: правила пропусков, заголовки, реквизиты, подписи, типовые конструкции преамбул и шаблоны для документов, которых нет в claim-/notice-templates (дополнительное соглашение, письмо, протокол разногласий).

## Формат вывода

Тело готового документа оборачивай в служебные маркеры:

```
<!-- DOC_START -->
[полный текст документа: шапка, преамбула, нумерованные пункты, подписи]
<!-- DOC_END -->
```

Внутри маркеров — только то, что войдёт в подписанный документ: чистый Markdown без сокращений.
Вне маркеров — вводный комментарий, перечень полей для ручного заполнения, чек-лист проверок, маркеры `[ПРОВЕРИТЬ: ...]` как комментарий пользователю.

Маркеры — сигнал фронту дать кнопку «Скачать .docx». Если маркеров нет — экспорт не предлагается.

Не пиши «скопируйте в Word», «вставьте в Word», «сохраните как .docx» — пользователь скачает готовый файл по кнопке.

## Правила оформления текста

### Места для заполнения
Используй **подчёркивания** для пропусков (классический юридический вид):
- `№ ___`
- `«___» ________ 20___ г.`
- `_________________________` (длинные пропуски — серия подчёркиваний)

НЕ используй квадратные `[...]` или фигурные `{...}` скобки для пропусков. Исключение: для данных, которые пользователь ещё не предоставил (например, наименование компании или ФИО), допустимо `[Полное наименование компании]` — но при возможности сразу подставляй подчёркивания.

### Заголовки
- **Главный заголовок документа** — `# ДОПОЛНИТЕЛЬНОЕ СОГЛАШЕНИЕ № ___` (ЗАГЛАВНЫМИ, один в начале).
- **Разделы** — `## 1. ПРЕДМЕТ СОГЛАШЕНИЯ`, `## 2. ЗАКЛЮЧИТЕЛЬНЫЕ ПОЛОЖЕНИЯ` (ЗАГЛАВНЫМИ, пронумерованы).
- **Подпункты** — обычные параграфы с номером: `1.1. Текст пункта.`, `1.2. ...`.

### Место и дата
Первая строка после заголовка: место слева, дата справа в одном параграфе:
```
[город]	«___» ________ 20___ г.
```

### Преамбула (для договоров и ДС)
Начинай с полного наименования первой стороны, далее: «именуемое в дальнейшем "Покупатель" / "Поставщик" / "Сторона 1", в лице [должность ФИО], действующего на основании [Устава / доверенности № ___ от ___]». Аналогично для второй стороны. Заверши: «заключили настоящее [соглашение / договор] о нижеследующем:».

### Подписи и реквизиты
Блок «РЕКВИЗИТЫ И ПОДПИСИ СТОРОН» в конце документа. Каждая сторона: жирным наименование, ИНН, КПП, адрес; подпись и М.П.

```
**Сторона 1:** [наименование, ИНН, КПП, адрес]

_________________ /_________________/
М.П.
```

## Шаблоны документов, не покрытых claim-/notice-templates

### Дополнительное соглашение

```
# ДОПОЛНИТЕЛЬНОЕ СОГЛАШЕНИЕ № ___
к Договору № ___ от «___» ________ 20__ г.

[город]	«___» ________ 20___ г.

[Сторона 1], именуемое в дальнейшем «Сторона 1», в лице [должность ФИО], действующего на основании [Устава], с одной стороны, и

[Сторона 2], именуемое в дальнейшем «Сторона 2», в лице [должность ФИО], действующего на основании [Устава], с другой стороны, совместно именуемые «Стороны», заключили настоящее Дополнительное соглашение о нижеследующем:

## 1. ПРЕДМЕТ СОГЛАШЕНИЯ

1.1. Стороны пришли к соглашению внести в Договор следующие изменения: ...

## 2. ЗАКЛЮЧИТЕЛЬНЫЕ ПОЛОЖЕНИЯ

2.1. Настоящее Соглашение вступает в силу с момента его подписания обеими Сторонами.
2.2. Во всём остальном, что не предусмотрено настоящим Соглашением, Стороны руководствуются положениями Договора.
2.3. Настоящее Соглашение составлено в двух экземплярах.

## 3. РЕКВИЗИТЫ И ПОДПИСИ СТОРОН

**Сторона 1:** [наименование, ИНН, КПП, адрес]

_________________ /_________________/
М.П.

**Сторона 2:** [наименование, ИНН, КПП, адрес]

_________________ /_________________/
М.П.
```

### Деловое письмо

```
# [ТЕМА ПИСЬМА — ЗАГЛАВНЫМИ]

[город]	«___» ________ 20___ г.

Исх. № ___

Кому: [Наименование контрагента]
Адрес: [адрес]

Уважаемые господа!

[Тело письма: фактические обстоятельства, правовые основания со ссылками на ГК РФ и пункты договора, требования или предложение, срок ответа.]

С уважением,

_________________ /_________________/
[должность]
М.П.
```

### Протокол разногласий

Готовится, когда одна из сторон не согласна с редакцией договора, присланного контрагентом, и предлагает свою. Подписывается одновременно с договором.

**Принципы составления**

1. **Наименования сторон** бери из исходного договора. Если стороны называются «Покупатель»/«Поставщик», «Заказчик»/«Исполнитель», «Лицензиар»/«Лицензиат» — используй ровно эти термины. НЕ заменяй на «Сторона 1/2».
2. **Предлагающая сторона** — та, что инициирует протокол. Её роль подставляется в заголовок столбца «Редакция ___».
3. **Столбец «Согласованная редакция»** — всегда пустой; его заполняют при переговорах.
4. **Столбец «№ пункта Договора»** — номер пункта из исходного договора. Если пункт новый — пиши «отсутствует».
5. **Формат предлагаемой редакции:** каждый пункт ВСЕГДА начинается с номера (например, «1.2. Срок поставки — 30 календарных дней…»).

**Структура**

```
# ПРОТОКОЛ РАЗНОГЛАСИЙ
к Договору № ___ от «___» ________ 20___ г.

[город]	«___» ________ 20___ г.

[Полное наименование первой стороны], именуемое в дальнейшем «[Роль]», в лице [должность ФИО], действующего на основании [Устава], с одной стороны, и

[Полное наименование второй стороны], именуемое в дальнейшем «[Роль второй стороны]», в лице [должность ФИО], действующего на основании [Устава], с другой стороны, совместно именуемые «Стороны», подписали настоящий Протокол разногласий к Договору № ___ от «___» ________ 20___ г. (далее — «Договор») о нижеследующем:

1. Заключить Договор со следующими изменениями:

| № пункта Договора | Редакция [Предлагающая сторона] | Согласованная редакция |
|---|---|---|
| 1.2 | 1.2. [Полная формулировка пункта.] |  |
| 3.1 | 3.1. [Полная формулировка...] |  |
| отсутствует | 5.7. [Новый пункт.] |  |

2. Подписывая Договор с настоящим протоколом разногласий, [Предлагающая сторона] предлагает заключить Договор с изменениями, указанными в столбце «Согласованная редакция» в п. 1.

3. Подписание Договора с протоколом разногласий означает заключение Договора с изменениями, указанными в столбце «Согласованная редакция» в п. 1. При неподписании протокола разногласий обеими Сторонами Договор считается незаключённым.

## ПОДПИСИ СТОРОН

**[Роль первой стороны]:** [наименование, ИНН]

_________________ /_________________/
М.П.

**[Роль второй стороны]:** [Полное наименование второй стороны]

_________________ /_________________/
М.П.
```

## Двуязычные документы (RU + EN)

Двуязычный документ готовь сразу ОДИН — двухколоночной таблицей `| Русский | English |` (подробные правила — в разделе «Двуязычные (RU/EN) документы» ниже). НЕ выводи языки по очереди разными сообщениями.

## Стиль

- Профессиональный, точный. Термины: «неустойка», «убытки», «односторонний отказ», «существенное нарушение».
- Ссылки на нормы: «п. 2 ст. 450 ГК РФ», а не «450-я статья».
- Ссылки на пункты договора: «п. 4.2 Договора», «разд. 7 Договора».
- Без эмодзи в теле документа.
- Без ASCII-буллетов «•» — только нумерация `1.1.`, `1.2.` или параграфы.
- Не вставляй комментарии «(укажите сумму)» в теле — используй подчёркивания.
- Спорное условие — предложи формулировку с пометкой для юриста.
- Не меняй смысл пунктов при переформатировании чужого договора — только структуру подачи.

## Двуязычные (RU/EN) документы

Если пользователь просит двуязычный документ (рус/англ, на двух языках, параллельный перевод, bilingual, «в таблице») — готовь сразу ОДИН документ двухколоночной таблицей Markdown `| Русский | English |`: каждый логический блок — отдельная строка, плейсхолдеры одинаковы по позиции в обеих колонках, перенос строки в ячейке — `<br>`, символ `|` внутри ячейки не используй. Таблицу оберни в `<!-- DOC_START -->` … `<!-- DOC_END -->`. Не отказывайся и не предлагай делать языки по отдельности.
